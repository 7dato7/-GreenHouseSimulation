# 🌱 GreenHouseSimulation — Цифровой агроном

**GreenHouseSimulation** — это учебный симулятор, демонстрирующий принципы прецизионного сельского хозяйства в условиях защищенного грунта. 

Проект реализует концепцию «умной теплицы»: управление посевами, климатом и поливом с учетом экономических ограничений и биологических циклов растений. Система написана на Python с применением ООП, структур данных и алгоритмов сортировки/поиска.

---

## 🧠 Сценарий использования

Пользователь выступает в роли **агронома-технолога** тепличного комплекса. Его задача — организовать непрерывный цикл выращивания овощных культур (томаты, огурцы, зелень, перец) с минимальными затратами ресурсов.

**Ключевые бизнес-процессы симуляции:**

- **Планирование посевов** — выбор культуры с учетом её биологических параметров (срок созревания, потребность в тепле и влаге).
- **Климатический контроль** — поддержание оптимальной температуры воздуха в каждой теплице (отклонение более 5°C замедляет рост).
- **Орошение** — восполнение влажности почвы с контролем расхода воды.
- **Экономика** — управление бюджетом и складскими запасами (энергия, вода, удобрения).
- **Сбор урожая** — фиксация полученной продукции и пополнение бюджета за счет её реализации.

**Цель игры:** достичь максимальной рентабельности тепличного хозяйства в условиях ограниченных ресурсов.

---

## 🎮 Интерфейс и навигация

Симуляция работает в консольном режиме. Процесс разбит на **дни (ходы)**. Пользователь пошагово планирует операции, а затем наблюдает их автоматическое выполнение.

---

### Доступные команды

| № | Команда | Назначение |
|---|---------|------------|
| **1** | Добавить задачу | Открывает подменю для планирования работ (посев, полив, сбор) |
| **2** | Следующий день | Запускает выполнение всех накопленных задач и обновляет состояние теплиц |
| **3** | История теплицы | Выводит хронологию всех операций, выполненных на указанном объекте |
| **0** | Выход | Завершает сессию симуляции |

---

### Подменю «Добавить задачу»

После выбора команды `1` пользователю предлагается указать тип операции:

- **Посев (1)** — требуется указать ID теплицы и название культуры. Доступны: `Томаты`, `Огурцы`, `Зелень`, `Перец`. Система проверяет наличие культуры в каталоге через бинарный поиск и резервирует бюджет на закупку семян.
  
- **Полив (2)** — для выбранной теплицы запускается процедура орошения. Расход воды фиксируется, влажность почвы повышается на 25% (но не более 100%).

- **Сбор урожая (3)** — команда актуальна только для теплиц со статусом **«созрело»**. После выполнения склад пополняется готовой продукцией, а бюджет увеличивается на сумму выручки.

---

### Подменю «История теплицы»

При вводе команды `3` система запрашивает ID теплицы. В ответ выводится полный журнал событий, накопленный с момента первого посева:
- дата посева и название культуры;
- дни полива с указанием объема использованной воды;
- момент созревания;
- дата сбора и объем полученного урожая.

## 🚀 Пример игрового цикла

Ниже представлен типовой сценарий работы с системой (от начала до получения первой прибыли):

1. **Посев:**  
   `1` → `1` → `Теплица_1` → `Томаты`  
   *Задача добавлена в очередь.*

2. **Переход к следующему дню:**  
   `2`  
   *Бюджет уменьшается на стоимость семян, статус теплицы меняется на «засеяно».*

3. **Полив (при необходимости):**  
   `1` → `2` → `Теплица_1`  
   *Влажность повышается.*

4. **Ожидание созревания:**  
   Повторять `2` до изменения статуса на «созрело».  
   *Томатам требуется 7 дней при оптимальной температуре 24°C.*

5. **Сбор урожая:**  
   `1` → `3` → `Теплица_1`  
   `2`  
   *Склад пополняется продукцией, бюджет увеличивается.*

6. **Проверка истории:**  
   `3` → `Теплица_1`  
   *Выводится хронология всех операций.*

## ⚙️ Архитектура и внутреннее устройство

Проект построен на **трехуровневой архитектуре**, характерной для консольных приложений с отложенным выполнением команд.

### 1️⃣ Слой представления (UI)
- **Методы:** `show_status()`, `add_task()`, `run()`
- **Задача:** организация диалога с пользователем, валидация ввода, форматирование вывода.

### 2️⃣ Слой бизнес-логики (Engine)
- **Класс:** `GreenHouseSimulation`
- **Задача:** управление временем, выполнение отложенных задач, проверка бизнес-ограничений (достаточность ресурсов, соблюдение климатических параметров).

### 3️⃣ Слой данных (Domain)
- **Классы-сущности:** `GreenHouse`, `Crop`, `ClimateSystem`, `Warehouse`
- **Структуры:** кастомный `LinkedList` для истории, `deque` для очереди задач, `dict` для склада.
